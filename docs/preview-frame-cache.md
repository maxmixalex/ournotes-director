# 时间轴的精确预览帧历史

此缓存改善已经显示过、播放时实际采集过，或在正常向前推进时顺便采集过的帧。它只在演出工作台明确的时间轴拖动过程中启用；键必须是请求的确切帧号，不会拿邻帧图片替代目标。普通 `SeekAsync`、松手后的最终定位、开始播放、读取模型参数和编辑操作仍要求准确的原生剧情状态。

## 状态与画质

`PreviewFrame.IsCached` 表示当前显示由帧历史恢复。`NativeStateSynchronized` 与诊断中的 `NativeFrame` 分别说明它是否与解释器的实际位置一致、解释器实际在哪一帧。拖动命中可以只改变显示帧；不能把这件事当作原生命令、物理、粒子或声音已经倒退。

停止拖动后，工作台提交 strict seek，逐帧执行原剧情以恢复目标状态并重新显示完整质量。播放会先恢复实际状态及完整质量，再启动时钟；模型参数检查、舞台编辑和项目提交也先同步真实状态。重建被取消后，下一次同步会重新建立原生状态，保留最后完成显示的画面直到恢复成功。

暂停定位时可保留完整图像。正常播放通过已绘制的最终 FBO 取得四分之一宽高的 RGBA 快照，不为此重新绘制场景。完整场景的这些缩略图明确标记 `ScenePreviewScale = 0.25`，`Pixels.Width/Height` 也是实际缩略图尺寸；它们不冒充完整尺寸输出。角色几何、动画与口型随准确帧一同保存。F1 全屏、独立人物和仅角色模式不接受缩略图代替完整预览。

## 容量和额外工作

每个场景会话独立持有一个 LRU 缓存，同时受 **128 MiB** 保留预算和 **1024 条目**上限约束。预算包括压缩 RGBA 及保守估计的几何、字符串和列表开销；保留的是私有不可变副本，返回给调用方的图像与投影矩阵也是独立副本。Brotli 使用低压缩等级；原始和压缩工作缓冲从 `ArrayPool<byte>` 租用，仅最终保留字节进入缓存。

128 MiB 是此缓存的保留预算，不是整个进程的内存上限。当前显示图像、池内工作缓冲、GL 纹理、场景资源及既有素材/音频缓存另有其生命周期和预算。单幅原始 RGBA 大于此预算时不进入帧缓存。

播放采集根据上次“额外读回 + 压缩”的实测成本限频，目标是平均每个源帧约 2 ms，间隔限制为 1–30 个源帧。该控制是反馈式的：首次驱动调用及个别慢调用仍可能超过目标；它不保证 30 fps，也不保证所有播放源帧都被保留。

正常向前推进时还可在目标前最多六个源帧上尝试额外的四分之一尺寸真实绘制。暂停 seek 的累计 **200 ms 软预算**、播放的 8 ms 软预算及上次采样成本决定是否开始采集；已开始的一次 GPU 绘制不能中途抢占，可能越过软预算，但之后不再启动新采样。加载第零帧不会为此额外等待。影片或静止画媒体可见期间跳过这些额外 Draw，避免改变媒体后处理的相机历史；最终已绘制 FBO 的读取不受此限制。

重建解释器的本次请求、松手后恢复当前缓存画面的严格定位，以及播放或参数读取前的严格状态同步，不再安排中间历史绘制。恢复仍执行全部原剧情、物理和粒子步骤，最终目标 FBO 仍可进入缓存；随后正常向前推进会重新启用机会式采集。这样避免刚重建的渲染器为了补存一张历史图，再支付一次冷绘制成本。

这是一项机会式近邻补充。帧窗口既不保证连续，也不保证跨度；实际 `FrameCache.Ranges` 才是当前保留范围。预算受限或驱动较慢时，可能只有一至几帧。

## 失效与剩余限制

重新加载来源或项目会创建新的场景缓存。项目内容/相对素材基准目录变化、实时编辑、舞台位置或独立预览变换变化、输出预览尺寸变化都会清除不再有效的图片；实时编辑在项目提交或原生重建之前还会禁止继续保留该临时状态。不存在跨项目共享的图片命中。本缓存不新增文件系统素材热更新协议；外部素材被替换时，仍须通过正常来源重载使运行中的场景和缓存一起更新。

从未缓存的逆向目标仍须重建解释器并从起点逐帧重演。精确历史可以显著降低已访问区域的连续回拖延迟，但没有解决任意长剧情的可复制原生检查点，也没有跳过原剧情物理、随机数、粒子、口型或命令步骤。松手时的最终原生同步因此仍可能需要等待。

## 回归与证据

`NativeTests --preview-frame-cache <10060 fixture> <output>` 输出 `preview-frame-cache-report.json`。报告保留真实 source、帧、画质、像素尺寸、缓存命中、原生帧、逐段耗时、实际保留范围及第一次访问中间帧的命中比例，不使用固定墙钟阈值。

门禁包括私有图像/几何所有权、池缓冲复用、条目/字节 LRU 边界；原始 10060 的历史采集开/关比较最终 RGBA、managed/native 参数、动画、口型、PCM、命令观测和粒子快照；连续不同目标的精确命中、未命中的真实回退、strict settle、播放恢复、编辑失效与重建中取消后的参数恢复。WinUI smoke 另通过真实鼠标在播放后连续回拖已访问区域，输出 `millsage-playback-reverse-trace.json` 与 `millsage-frame-history-workbench.json`，区分拖动期间的历史呈现和松手后真实 native 同步。

软件 Mesa/llvmpipe 的诊断只能说明该软件渲染环境；不能当作真实 Windows GPU 或用户机器的硬件性能结论。最终发布应引用同一提交的 CI 报告和实际范围，不把缓存命中延迟写成所有首次逆向定位的耗时。

### 初版本地验证记录

2026-10-21 禁止严格恢复期间额外历史绘制之前，Linux llvmpipe 门禁为 **77/77**。素材是原始 `10060`，主场景为 960×540、1×采样；先按 0.1 秒间隔正常定位 115.0–116.0 秒，之后再连续逆向请求。以下是该次运行的诊断，不能外推为所有驱动或所有时间段的性能承诺。

| 场景 | 本次结果 |
| --- | --- |
| 十个不同的完整已访问帧逆向命中 | 8.35–18.13 ms，中位数 9.75 ms；每次 0 个模拟步骤，native 保持第 3480 帧 |
| 首次请求未手动访问的中间帧 3479、3478、3476、3475 | 3/4 已被机会式采集；命中耗时 1.41–5.06 ms，实际图像 240×135；未命中 3475 真实重演 3475 步，耗时 11.45 s |
| 松手 strict 恢复 115 秒 | 8.29 s；真实重演 3450 步，完整像素及人物状态与参考一致 |
| 未缓存的 114 秒逆向定位 | 7.42 s；真实重演 3420 步；再次请求同帧为 9.20 ms |
| 开始回拖前的保留量 | 30 帧，5,487,112 字节；128 MiB 保留预算内 |

开始回拖前的实际范围是 `0`、`3445`、`3450`、`3452–3453`、`3455–3474`、`3476–3480`。其中有空洞，测试不会用邻帧掩盖这些空洞。完整报告同时保留播放采样关闭/开启的总耗时（本次分别 3462.60 / 2453.09 ms）；顺序运行受 CPU 调度、驱动与冷暖状态影响，该差值不构成采样带来加速的证据，额外成本应看单独记录的读回和压缩时间。

回归文件为 `preview-frame-cache-report.json`；本地完整证据目录是 `/tmp/ournotes-frame-cache-verified-evidence`。Windows Native AOT 和真实 WinUI 的结果应取同一提交的 CI 附件，另行记录其软件驱动与实际覆盖率。

### 严格恢复路径的补充优化

Windows 初版证据显示，严格恢复 115 秒以及未缓存回退到 114 秒时，各额外绘制了一张近邻历史图，单次采集分别耗时 2263.72 ms 和 2259.38 ms。200 ms 软预算无法中断已经开始的冷绘制。本次禁止这些恢复请求采集中间历史图，不改变最终帧的渲染与缓存。

补充后的完整本地门禁为 **85/85**（Linux Mesa 25.2.8 / llvmpipe，含原有断言；播放采样次数会影响实际断言总数）。`/tmp/ournotes-frame-cache-recovery-evidence/preview-frame-cache-report.json` 记录：

| 请求 | 原生行为与历史采集 |
| --- | --- |
| 松手严格恢复 115 秒 | 完整重演 3450 步；中间采集计数和耗时均零增量；8.91 s |
| 未缓存回退到 114 秒 | 完整重演 3420 步；中间采集计数和耗时均零增量；9.04 s；最终目标仍可精确命中 |
| 重建后正常向前三帧 | 同一原生会话推进 3 步，重新采集 1 张真实近邻图；最终目标再次精确命中 |
| 从缓存画面严格向前追赶到 115 秒 | 同一原生会话推进 27 步，中间采集零增量；135.66 ms |
| 参数读取及播放前恢复 | 原生状态与最终完整画面正确，中间历史采集零增量 |

此次重新启用采集时的一次冷绘制仍用了 831.68 ms，说明正常前进的软预算依然不构成最坏延迟保证。两次 Linux 运行不是同场 A/B 对照，不能从总耗时推导固定提升比例；可直接确认的变化是严格恢复路径不再承担额外历史绘制。重建解释器、准备 GPU 资源和真实逐帧模拟仍是待优化成本。
