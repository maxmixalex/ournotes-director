## 交互绘制规则

仅鼠标按住拖动时按已观察到的渲染成本选择完整、1/2、1/4 的场景绘制尺寸；软件光栅器采用 1/4。保持完整呈现缓冲、原生指令/物理/音频/捕获时序、命中坐标和项目不变。低分辨率仅作用于昂贵的场景与景深绘制，保留线性 HDR 并通过普通最终颜色/透明度解析；不替换原游戏效果，也不另建动画求值器。

状态栏明确显示交互预览比例。正常暂停、松手或捕获丢失会请求最后一帧的完整质量。离开工作台取消旧请求，回来恢复完整质量。PNG、视频、帧序列导出仍使用原项目及完整渲染路径。

## 验证要求

### 本地实测

使用 .NET SDK 10.0.100、Linux Mesa/EGL、固定的 10462 双角色归档与真实 Cubism Core/FFmpeg。Release 构建零警告、零错误。桌面逻辑 1116 项、真实剧情分析 19 项、受影响预览编辑 9 项、真实舞台 22 项、交互质量与取消 18 项通过。

真实时序对照按“串行、预取、预取、串行”运行，每次使用独立原生分析器与 PCM 缓存：

| 方式 | 第一次 | 第二次 | 两次平均 |
| --- | ---: | ---: | ---: |
| 串行解码 | 5713.3 ms | 4421.1 ms | 5067.2 ms |
| 四路预取 | 3115.4 ms | 2545.3 ms | 2830.3 ms |

此机器此样本平均减少 44.1%，不是所有素材或整段导入时间的保证。四次均为 144 条完全相同的原生指令时序、终点第 3363 帧；抽查的两条语音完整 PCM 逐样本一致。真实阻塞解码进程取消后 11.9 ms 返回，子进程已退出、临时输入已删除。

同源准备阶段九组交替测试中，旧路径中位约 8.0 ms、4.346 MB 分配，直接展开约 5.1 ms、2.478 MB；1600 行合成场景的主要收益是省去重复对象和采样。用户可感知的真实分析改善以上述原生时序对照为依据。

### Windows 原生结果与首次拖动绘制修复

`fda185c` 的 [Windows run 39266685545](https://github.com/maxmixalex/ournotes-director/actions/runs/39266685545) 已完成编译、Native AOT、打包和原生验证。实窗通过 279 项，包括三工作台 F1、最大化布局恢复、输入控件焦点排除、项目替换与取消、实际分组和行高操作；随后失败于原有暂停拖动门槛。失败发生在约 244 秒，没有触发新的总时限或无进展限制。

同次 Windows 原生剧情分析的串行两次平均为 3063.0 ms，预取为 2268.4 ms，此样本减少 25.9%；144 条指令时序、终点第 3363 帧和语音 PCM 保持一致。真实阻塞解码取消在 6.5 ms 返回，子进程退出、临时输入清除。

拖动轨迹显示输入约 0.94 ms 内进入原生定位，但第一帧花费 2956.3 ms，其中场景绘制 2948.3 ms、模拟 5.2 ms、回读 2.2 ms；呈现排队与显示仅约 0.6 ms。交互比例已为 1/4，原生会话未重载。显式着色器编译计时为零，不能排除驱动在首次 draw 时生成机器码。

用该实窗生成的原项目进行逐 pass 对照，定位了既有 16×16 预热的两个缺口：实际缩小画布和半尺寸纹理并非 2 的幂；舞台 main 带深度/模板附件，而角色 layer 只有颜色附件。二者会触发不同的原生绘制变体。Linux llvmpipe 的独立诊断进程测量如下：

| 私有准备配置 | full frame 0 后首次 quarter frame 3 |
| --- | ---: |
| 原有 16×16、无深度附件 | 1922.7 ms |
| 17×17、无深度附件 | 1253.9 ms |
| 17×17、分别准备无/有深度附件的 Blur | 373.2 ms |
| 生产准备：上述两类 Blur 与图层合成 | 338.4 ms |

最后一组背景与角色 Blur 的第二 pass 分别只需 0.65、0.84 ms；随后两个 quarter 帧约 51.1、47.1 ms。七个相同帧与比例的完整像素哈希在对照间一致。这是同一软件绘制设备上的因果测量，Windows 实窗仍按原门槛独立验收。

生产准备现在根据真实 full、1/2、1/4 尺寸，分别保留原纹理和向上取整半尺寸是否为 2 的幂的特征，映射为小尺寸 16、15、17 并去重；同时准备无/有深度附件的原版 Blur 和角色图层合成。所有操作在私有小画布中完成并回读，随后连同其深度附件释放。不会调用场景绘制或推进原生播放器，也不会修改真实画布附件、角色、捕获、导出设置或项目文件。

生产代码再测的后续 quarter 帧为 52.4、49.8 ms，七个采样帧像素哈希仍与原代码一致。正式 Release 编译零警告、零错误；真实舞台 22 项、交互画质与原生状态/取消 18 项再次通过。
