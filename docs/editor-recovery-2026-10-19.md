## 交互绘制规则

仅鼠标按住拖动时按已观察到的渲染成本选择完整、1/2、1/4 的场景绘制尺寸；软件光栅器采用 1/4。保持完整呈现缓冲、原生指令/物理/音频/捕获时序、命中坐标和项目不变。低分辨率仅作用于昂贵的场景与景深绘制，保留线性 HDR 并通过普通最终颜色/透明度解析；不替换原游戏效果，也不另建动画求值器。

状态栏明确显示交互预览比例。正常暂停、松手或捕获丢失会请求最后一帧的完整质量。离开工作台取消旧请求，回来恢复完整质量。PNG、视频、帧序列导出仍使用原项目及完整渲染路径。

## 验证要求

新增纯策略回归和真实双人场景绘制回归：预算变化不提前发布旧画面；原生时间/会话/命中边界保持；恢复完整质量后与独立原生重放逐像素一致；保留的帧像素不被改写；向后定位仍保持交互预算；项目文件无修改。

原 Windows GUI 检查仍要求真实标尺输入 1.4 秒期间至少 4 个不同原生帧及不同像素，松手达到最后输入帧；新增必须恢复完整质量。原参数、透明画布、PNG/MOV 输出和性能阈值不放宽。

## 从 64fe6fe 继续改进

本轮基线为 `64fe6fe9039e3776d9c021cc9e4d657267cccf30`，沿用现有分支与 PR #5。三个子代理分别负责显卡、剧情性能和交互审查，主代理集成并核对真实验证结果。

- 显卡设置同时核对编辑器与导出引擎的 Windows 覆盖项，正确处理外部删除覆盖、未保存与待重启状态。呈现设备取自已经附加的交换链。原生桥 ABI 升到 2，候选适配器须完成交换链、WGL 共享纹理和 FBO 后才接受。
- 剧情准备直接展开 SceneDocument、提取角色关联，省去旧关键帧编辑器的时间扫描与采样。时序分析最多四路音频预取、八条前瞻，沿用 128 MiB PCM 缓存；单条推测解码限 8 MiB，超限声音实际用到时完整解码。原生指令求值顺序不变，取消会回收子进程。
- “显示所选片段”同时解除排除它的筛选、展开父组并滚动到可见位置。同源项目替换也清理旧手势、范围、分组与局部缩放；播放与导出等待最后一次定位并核对文档所有者。
- 画质恢复同时检查实际预算与已发布像素，覆盖质量切换两侧被取消的情况。取消贯穿原生定位后的 XAML 呈现等待，避免清掉旧画面后继续等待 30 秒。
- F1 全屏补齐系统恢复窗口时的外框和布局恢复；实窗回归覆盖 F1/F1、F1/Esc、先前已最大化状态和监视器内部输入框焦点。

### 本地实测

使用 .NET SDK 10.0.100、Linux Mesa/EGL、固定的 10462 双角色归档与真实 Cubism Core/FFmpeg。Release 构建零警告、零错误。桌面逻辑 1116 项、真实剧情分析 19 项、受影响预览编辑 9 项、真实舞台 22 项、交互质量与取消 18 项通过。

真实时序对照按“串行、预取、预取、串行”运行，每次使用独立原生分析器与 PCM 缓存：

| 方式 | 第一次 | 第二次 | 两次平均 |
| --- | ---: | ---: | ---: |
| 串行解码 | 5713.3 ms | 4421.1 ms | 5067.2 ms |
| 四路预取 | 3115.4 ms | 2545.3 ms | 2830.3 ms |

此机器此样本平均减少 44.1%，不是所有素材或整段导入时间的保证。四次均为 144 条完全相同的原生指令时序、终点第 3363 帧；抽查的两条语音完整 PCM 逐样本一致。真实阻塞解码进程取消后 11.9 ms 返回，子进程已退出、临时输入已删除。

同源准备阶段九组交替测试中，旧路径中位约 8.0 ms、4.346 MB 分配，直接展开约 5.1 ms、2.478 MB；1600 行合成场景的主要收益是省去重复对象和采样。用户可感知的真实分析改善以上述原生时序对照为依据。
